# 赛事管理与成绩结果设计

日期：2026-10-09  
状态：待用户审阅  
范围：赛事配置、参赛名单、拉力计时赛段、结果审核与发布、Excel 工作簿

## 目标

让网页后台可以建立一场可在小程序中查看和录入成绩的赛事，并统一管理赛事组别、参赛选手、赛段记录和最终结果。网页与小程序继续使用同一个 CloudBase 环境和赛事 ID；网页管理员登录后管理赛事和全部成绩，小程序工作人员继续按现有赛段及字段权限录入。

未来小程序报名入口会把确认后的选手加入赛事参赛名单。本次设计预留名单来源字段，但不实现报名流程。

## 已确认的产品规则

- 每场比赛可以定义自己的参赛组别，例如经典车组、前驱街车组。
- 首版可用的赛制为“统计 / 拉力赛”。“计分”作为暂不可用的入口保留；没有配置并确认积分规则前，不计算或发布计分结果。
- 拉力赛支持 SS1 至 SS9 中的 1 至 9 个赛段。赛事配置决定实际使用的赛段数量。
- 排名方式为“最佳赛段”或“累计赛段”。最佳赛段取该选手所有有效赛段中最快的一段；累计赛段把有效赛段成绩相加。排名计算包含该段罚时；单段成绩页保留原始发车/收车时间、原始赛段用时和罚时，避免把罚时重复加到显示值。
- 正式发布结果使用赛事配置的排名方式；每次导出工作簿时，管理员仍可单独选择导出“最佳成绩”或“总成绩”，不改变赛事已配置的正式排名方式。
- 网页成绩预览按组别展示并可排序；网页管理员可以查看、修改并发布全部赛段成绩。
- 赛事页面发布与成绩结果发布分开：创建并发布赛事后，小程序赛事列表可见该赛事；成绩只有在网页管理员确认发布后才显示为正式结果。
- 赛事名称、日期、地点、封面和说明沿用现有赛事模板创建流程。新发布的赛事仍按发布时间排在小程序赛事列表前面。
- 参赛名单首版支持网页手动维护和 Excel 工作簿导入。选手记录包括车号、组别、车手姓名和车型；车号在同一赛事内唯一。
- 网页沿用一个管理员账号和密码登录。此登录拥有网页内全部赛事和成绩的管理权限；小程序工作人员仍使用小程序账号和已配置的赛段、发车时间、收车时间、罚时权限。
- 成绩工作簿包含总成绩页及有成绩的 SS 赛段页。总成绩页保留车号、赛段成绩和最终有效成绩，不导出组别、车手姓名、车型。各 SS 页包括车号、发车时间、收车时间、赛段用时；该赛段至少一人有非零罚时才出现“罚时”列。导出列宽需完整显示表头和时间。

## 当前实现与需要补齐的部分

- `score-review-web/server.js` 和 `score-review-web/cloud-store.js` 已提供网页管理员会话、动态赛事读取/发布和按 `eventId + stage` 读取/保存 `work_records` 的基础接口。
- `events` 文档目前只保存赛事展示信息，尚无赛制、组别、赛段数、排名方式或参赛名单。
- 小程序赛事详情可以读取网页发布的赛事；从赛事详情进入工作后台时会传递赛事 ID。工作后台和云函数按赛事 ID、赛段共享 `work_records`，现有工作人员权限会在云函数端校验。
- 小程序工作后台目前固定显示 SS1 至 SS9，且可以自由输入车号，没有读取赛事参赛名单。
- 小程序成绩审核/结果页目前主要使用静态示例数据，没有从网页后台读取动态赛段成绩或正式发布结果。

## 设计方案

沿用现有 CloudBase 作为唯一数据源，不另建第二套赛事或成绩库。网页沿用现有 Apple 风格后台，增加赛事设置、参赛名单、赛段数据和结果预览流程；小程序动态读取对应赛事配置和已经发布的成绩快照。

### 数据模型

**赛事 `events` 文档**在现有展示字段上扩展：

- `competitionType`: `statistics` 或 `scoring`。
- `discipline`: 首版拉力赛使用 `rally`。
- `stageCount`: 1 至 9。
- `rankingMode`: `bestStage` 或 `sumStages`。
- `groups`: 有序组别列表，包含稳定 ID 和显示名称。
- `published`: 赛事是否出现在小程序赛事列表。
- `resultsPublished`、`resultsPublishedAt`: 当前正式结果快照的发布状态和时间。

旧赛事缺少这些字段时继续保留现有展示和成绩读取方式；不能因打开新功能而清空、覆盖或错误迁移旧成绩。旧成绩的车号如果不在新名单中，应在网页结果预览标成“未匹配名单”，由管理员处理，不静默丢弃。

**参赛名单 `event_participants` 集合**：每条记录关联 `eventId`，保存 `carNumber`、`groupId`、`driverName`、`vehicle`、`source` 和时间字段。`source` 首版为网页手动或 Excel 导入，未来可扩展为小程序报名。数据库写入和 Excel 导入都校验同一赛事内车号唯一、组别属于该赛事、必填车号有效。

**赛段 `work_records` 集合**继续使用现有 `eventId + stage` 数据键，保持小程序录入端兼容。每条成绩分别保留原始计时赛段用时、罚时分项/合计和排名用时；原始计时赛段用时 = 收车时间 − 发车时间（支持跨午夜），排名用时 = 原始计时赛段用时 + 罚时。SS 工作表及总成绩页的各 SS 列显示原始赛段用时，罚时单独显示；最终有效成绩按排名用时计算，避免重复加罚。网页保存和小程序保存都不能抹去对方维护的名单或赛事设置。

**正式结果 `event_results` 集合**保存发布时的结果快照，关联 `eventId`，包括排名方式、分组排序后的总成绩与赛段成绩、发布时间和版本。小程序公开结果默认只提供车号、组别、赛段用时、有效成绩和排名，不公开名单中的姓名、车型。网页编辑尚未发布的记录不会悄悄改动小程序已发布的结果；管理员再次发布才替换快照。

### 网页操作流程

1. 管理员新建赛事：从现有赛事复制封面和文字，设置赛事类型、拉力赛、赛段数量、组别和排名方式，再发布赛事。
2. 管理员在参赛名单页手动添加选手或导入 Excel；提供预览、错误行提示和重复车号检查。
3. 管理员在成绩页按赛事和 SS 查看、修改记录及审核状态；表格可按组别筛选/分组，并按车号或成绩排序。录入工作人员通过小程序共享同一批成绩。保存请求带上所读取的赛段版本；如果另一位工作人员已更新该赛段，服务端拒绝旧版本整包覆盖并返回冲突信息，网页保留本地修改、提示刷新并合并，不能静默覆盖较新的数据。
4. 管理员打开结果预览，查看按赛事官方排名方式计算的分组排名、缺失赛段和未匹配车号，修正数据后可发布正式结果；导出工作簿时单独选择“最佳成绩”或“总成绩”。
5. “计分”选项呈现规则尚未配置的说明并禁用结果计算/发布，不伪造积分。

网页可视区域沿用现有响应式布局；宽表格在表格容器内横向滚动，不推动整页超出屏幕。

### 结果计算和缺项处理

- 仅由有效的发车/收车时间产生赛段成绩；空记录和 `00:00:00.000` 不作为有效用时。
- 排名值使用“收车减发车 + 罚时”。展示时保留原始发车、收车、罚时和赛段用时，便于核对。
- `bestStage`：从该车已有的有效赛段成绩中取最短用时；没有任何有效赛段则不排名。
- `sumStages`：加总有效赛段成绩。缺少配置赛段的选手在预览中标为“成绩不完整”，保留其已有赛段数据；是否仍可进入累计赛段正式名次尚待确认，在确认前不为不完整成绩分配名次。
- 赛事配置的排名方式控制预览排名和发布的正式结果。导出选择单独计算：最佳成绩导出取每个车号有效 SS 排名用时中的最小值；总成绩导出将有效 SS 排名用时相加。导出模式不覆盖或修改官方结果。
- 结果按组别分别排名，组内按最终用时从快到慢排序。网页可以查看所有组别；总成绩工作表按组别顺序排列，但按照既有要求不显示组别列、姓名和车型。
- 页面及导出均只生成至少有一条有效成绩的赛段工作表；在有成绩的 SS 序列中保留空白赛段列，直到最后一个有数据的赛段。
- 单段工作表中的罚时列按该 SS 是否存在任意非零罚时决定；若没有人有罚时则整列省略。

### 小程序数据流

- 小程序赛事列表继续从网页后端的公开赛事接口读取；事件文档包含必要的赛制、赛段数量和组别摘要。
- 赛事详情进入工作后台时继续传 `eventId`。工作后台根据赛事 `stageCount` 显示可用 SS，并读取该赛事参赛名单供搜索/选择车号，避免工作人员把成绩写入别的赛事。
- 工作后台继续走现有账户云函数写入 `work_records`，服务端既有工作人员赛段和字段权限保持生效。网页管理员通过受密码保护的后端接口读取、编辑相同的 `work_records`。
- 小程序普通用户只读取已发布的 `event_results` 快照；未发布的编辑记录不公开。赛事详情结果区根据赛事组别和发布快照展示动态结果，旧的内置赛事展示继续兼容。
- 公开接口只返回赛事展示信息、选手公开字段及已发布结果；不得公开网页密码、云数据库密钥或工作人员隐私字段。

### Excel 导入和导出

- 参赛名单和赛段成绩都支持 Excel 工作簿导入。导入界面列出所有工作表，管理员可选择一个或多个工作表逐个预览、映射字段并确认导入；不会把多张表误读为一张平面表，也不会静默忽略未选工作表。名单导入最小必需列为车号和组别，姓名、车型可为空。成绩工作簿可以包含“总成绩”及 SS 工作表；每个 SS 工作表映射到相应赛段并导入发车、收车及罚时，预览时逐表提示错误和重复车号。导入的汇总页只用于核对，不作为赛段数据源；导入完成后由赛段数据重新计算总成绩。
- 成绩导出为 `.xlsx` 工作簿。点击导出时可选择“最佳成绩”或“总成绩”；该选择只影响总成绩页的最终有效成绩计算，不修改赛事官方排名设置。工作簿总成绩页在前，后续为有效数据所在的 SS 页。
- 每张 SS 工作表展示原始发车时间、收车时间、原始赛段用时，以及该 SS 存在非零罚时才显示的罚时列；罚时参与总成绩页的有效成绩计算，但不与原始赛段用时列重复相加。
- 总成绩页列为车号、所有实际赛段原始用时、最终有效成绩；不包含上传人、审核状态、上传时间、组别、姓名、车型或通用“赛段”列。各 SS 列显示不含罚时的计时赛段用时，最终有效成绩才按本次导出所选的“最佳成绩”或“总成绩”模式计入罚时。
- 工作表列宽按列用途设定为完整时间字段可见，避免当前导出中收车时间被截断；时间格式统一保留毫秒三位。

### 接口边界

- 现有受保护的 `/api/events` 扩展赛事配置保存；公开赛事列表返回小程序展示所需的赛事配置。
- 新增受保护的参赛名单查询、批量导入/新增/编辑接口。
- 现有受保护的 `/api/work-records` 扩展完整编辑所需字段，继续以 `eventId + stage` 读写共享成绩。
- 新增管理员结果预览/发布接口，以及按赛事读取已发布结果的公开接口。
- 工作记录保存使用赛段版本检查；并发冲突需返回可识别错误，网页保留未提交修改并要求刷新/合并，拒绝旧版本的整段覆盖。
- 继续使用当前网页单一账号密码会话；云数据库密钥留在服务端环境变量中。

## 分步交付

1. 赛事配置、组别与参赛名单的网页管理；赛事详情和工作后台按赛事 ID、赛段数量、名单完成动态接入。
2. 网页赛段数据管理与结果预览、分组排序、排名计算和结果发布；小程序展示动态发布结果；完成要求的多工作表 Excel 导入和列宽正确的 `.xlsx` 导出。
3. 后续单独实现小程序报名入口，让报名申请在审核后创建或更新 `event_participants`，本次不实现。

## 验收标准

- 网页创建并发布的拉力统计赛事显示在小程序赛事列表最前面；赛事详情中的录入进入同一个 `eventId`。
- 赛事可以设置 1 至 9 个 SS、多个组别、唯一车号和参赛选手；名单及成绩工作簿导入可以逐表选择、预览和映射，并发现无效/重复车号。减少赛段数时，已有高编号赛段数据不得静默删除，必须保留并提示管理员如何处理。
- 小程序工作人员只看到赛事配置的赛段并从赛事名单选择车号；已有云函数赛段和字段权限继续有效。
- 网页管理员可在一个赛事内查看、修改各赛段数据、预览组别排名，并按既定规则发布或重新发布；未发布变更不会出现在小程序普通用户结果中。
- 导出对话框可以分别选择“最佳成绩”和“总成绩”，结果工作簿总成绩页按选择计算有效成绩，同时保留每个有数据赛段的 SS 列；该选择不改变已发布的赛事官方结果。
- 小程序工作人员与网页管理员同时编辑同一赛事数据时，过期写入不能覆盖已保存内容；冲突有明确提示且网页未提交修改得以保留。
- 最佳赛段、累计赛段、罚时、缺失赛段均按本文规则得到可预测结果；计分模式不会产生未经配置的排名。
- `.xlsx` 文件含总成绩与有数据的赛段工作表，字段符合用户约定，时间完整可见到毫秒，罚时列仅在该 SS 有非零罚时的情况下出现。
- 老赛事和现有 `work_records` 数据仍可读取；不匹配参赛名单的旧车号被提示处理且不丢失成绩。
- 网页管理员端需要有效密码；公开小程序接口只返回公开赛事/名单字段和已发布结果。

## 仍需用户在规格审阅时确认的具体规则

- 累计赛段中缺少赛段的成绩是否可按已完成部分进入正式排名，尚未定案；在明确规则前，预览标记为不完整且不排名。
- 组别不显示在总成绩 Excel 页，但网页预览会分组并在组内排序。
- 小程序公开结果默认只暴露车号、组别、赛段用时、有效成绩和排名；名单中的姓名、车型不通过公开接口返回，除非另有明确需求。
